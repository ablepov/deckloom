# Готовые публикации v1

Данные не содержат S3 settings, credentials, HTML или исполняемые callbacks. `publications.validate/parse`, `validateCatalog/parseCatalog`, `files`, `verify`, `viewModel`, `downloadModel`, `prepare` экспортированы из `deckloom/node`. `verify` получает callback чтения относительных файлов, проверяет bytes/SHA-256 и PNG geometry. Host владеет хранением, авторизацией и активацией. Версия протокола независима от npm version.

`prepare(project,{deckId,outputRoot,projectId,sourceId,slideIds,downloads?,shareId?,onProgress?})` создаёт новую папку, не перезаписывает существующую. PNG всегда; downloads по умолчанию PDF. Один offline HTML export даёт PNG/PDF и источники для optional semantic PPTX; отдельная повторная загрузка авторских assets для PPTX не выполняется. Установленные redistributable pinned fonts/metrics задаёт consumer. Без configured semantic-source-v1 native форматы отклоняются. Неподдержанный актуальный native source возвращает PUBLICATION_NATIVE_EXPORT_FAILED без готового manifest; частичная локальная папка не является публикацией. Все промежуточные ресурсы находятся в собственном temp и удаляются после подготовки, в переносимый выпуск попадают только declared PNG/downloads и manifest.

Manifest: `{publicationVersion:1,sourceId,projectId,deckId,releaseId,shareId,title,publishedAt,generatedAt,engineVersion,sourceSha256,slides,downloads}`. releaseId — UUID неизменяемого выпуска, shareId — 16 случайных байт в lower-case hex; scope project/deck устойчив. sourceSha256 фиксирует подготовленный набор, generatedAt относится к его генерации. Слайды упорядочены массивом `{id,name,width,height,image:{file,bytes,sha256}}`; id устойчив к перестановке/переименованию, Monq использует существующий comment-slide-ids mapping. image.file начинается `slides/`, заканчивается `.png`. downloads содержит только реально готовые `pdf`, `pptx`, `pptx-fonts`, значения `{file,bytes,sha256}` в `downloads/` с расширениями `.pdf/.pptx/.zip`. Нет обещания доступности отсутствующих форматов.

Host storage layout MVP: `<prefix>/releases/<releaseId>/manifest.json` и относительные файлы выпуска. В конце publisher условно заменяет `<prefix>/catalog.json`: `{catalogVersion:1,revisionId:<UUID>,entries:[{projectId,deckId,shareId,releaseId,title,publishedAt}]}`. Host обеспечивает безопасную первоначальную инициализацию и сериализацию публикаций средствами своего хранилища; обновление catalog проверяет прежнюю ревизию/ETag. Отказ CAS означает конфликт, не молчаливый last-write-wins. Конкретная стратегия Monq и особенности S3 описаны в записи consumer, не являются API движка. Стабильная share-ссылка разрешается по текущему catalog; открытая страница получает fixed releaseId API и не переключается посреди просмотра. Нельзя активировать manifest с непроверенными/отсутствующими файлами. Повтор после неизвестного ответа commit сначала читает catalog и проверяет releaseId. Старые публикации автоматически не удаляются этим контрактом.

`viewModel(manifest,file=>hostUrl)` возвращает существующий registered v1 DTO с PNG и отсутствующим HTML. `downloadModel` возвращает capabilities `{decks:[{deckId,mode:'ready',pdf,pptx,fonts,links:{format:{url,filename}}}]}`. В ready режиме общий viewer скачивает готовый файл без POST/job/Chromium. Host обеспечивает корректные Content-Type/Content-Disposition и разрешённые URL. Viewer config `{apiBase:'/api/...fixed-release...',published:true,comments:false}` отключает обновление composition; комментарии подключаются отдельно после собственного согласованного доступа.

Ограничения: до 1000 слайдов, PNG до32MiB, downloads до100MiB каждый, уникальные file bytes до300MB, manifest/catalog JSON до1MiB; все paths относительные без traversal. Это per-publication guards, не замена учёта общей квоты бакета и staging. Приватность конкретного host не следует из случайности shareId.
