# Контракт Project Deck Slide

Этап B1, 20 октября 2026 года. Контракт реализован в рабочей копии через [B2](../tasks/b2-normalization-2026-10-20.md), [B3](read-api-v1.md) и [B4](render-v1.md): нормализация, registered/discovery, проекции чтения и versioned renderer с согласованными размерами/состояниями. `contractVersion: 1` — контракт конфигурации HTML-адаптера, а не версия npm-пакета и не будущая схема сохраняемого документа. В опубликованном 0.1.0 этот контракт ещё не поддерживается; новый релиз не назначен.

Текущее поведение описано в [baseline 0.1](../baseline-0.1.md), переход — в [карте миграции](../migrations/project-contract-v1.md), направление — в [roadmap](../roadmap.md). B1 описывает, но не реализует renderer, валидатор, проекцию чтения или хранилище презентаций.

## Основные решения

Дополнение22.10.2026: необязательное поле Project.downloads настраивает скачивание в общем viewer. Это отдельный namespace; data адаптера остаётся opaque. [Контракт скачивания](viewer-downloads-v1.md).

| Решение | Результат |
| --- | --- |
| Project — граница подключения | В одном namespace определены колоды, адаптер HTML, исходный корень артефактов и явно публикуемые ресурсы |
| Deck — конкретная презентация | Порядок массива slides определяет порядок показа, рендера и последующего экспорта |
| Slide — экземпляр в колоде | Постоянный ID не зависит от позиции, названия и шаблона; повтор одного шаблона создаёт другой экземпляр |
| Два источника данных не смешиваются | Registered использует конфигурацию; discovery обнаруживает артефакты и имеет только возможности чтения |
| Артефакт не определяет содержание | Наличие старой папки не добавляет слайд; отсутствие PNG не исключает зарегистрированный HTML-слайд |
| Текущие пути могут сохраняться | Legacy layout задаёт технический номер файла отдельно от позиции; новый stable layout использует ID |
| Оформление принадлежит адаптеру | Движок не интерпретирует data и не требует шаблоны/блоки от HTML-проекта |

## Project

| Поле | Правило v1 |
| --- | --- |
| `contractVersion` | Обязательно, число `1`; неизвестная версия отвергается без автоматического угадывания |
| `id` | Обязательный постоянный ID проекта; уникален в подключаемом наборе проектов |
| `mode` | Обязательно: `registered` или `discovery`; нельзя смешивать источники по колодам |
| `root` | Обязательный абсолютный путь к исходному корню артефактов. Сохраняет смысл root из 0.1; не становится автоматически корнем публичного HTTP-сервера |
| `decks` | Обязательный массив Deck; пустой массив допустим для проекта без созданных презентаций |
| `artifacts.layout` | `stable` по умолчанию в registered либо явный `legacy`. Discovery требует явного `artifacts: { layout: 'legacy' }` в первом контракте |
| `renderDocument` | Функция адаптера, обязательная для операции рендера registered-проекта; viewer/scanner могут читать готовые артефакты без неё |
| `viewer` | Настройки title/favicon/storagePrefix/legacyDeckId; новые проекты по умолчанию разделяют состояние по project.id, явный storagePrefix сохраняет старый namespace |
| `staticMounts` | Явные HTTP mount → абсолютный путь. Корневой mount и зарезервированные маршруты движка не перекрываются; внешняя папка не публикуется только потому, что она доступна renderer |
| `data` | Необязательный объект данных адаптера; движок не интерпретирует его |
| Хуки 0.1 | validateDocument, renderSpec, renderQa, reportName, measureLayout, issueCount, layoutOptions сохраняют свои роли; унификация их исполнения относится к C3 |

Для versioned-конфигурации поля движка закрыты: опечатка в известной структуре является ошибкой. Произвольные поля размещаются в data. Данные HTML-адаптера могут содержать собственные значения и функции в доверенном Node-конфиге; B1 не обещает их JSON-сериализацию. Сохраняемый документ F1 имеет [отдельную JSON-схему](presentation-document-v1.md); действующий config не сериализуется и не мигрирует автоматически.

Отсутствующий root на диске не является структурной ошибкой registered-проекта: до первого рендера все артефакты могут иметь состояние missing. Чтение не создаёт каталог автоматически. Для discovery отсутствующий либо нечитаемый root — ошибка источника, а не доказательство пустого набора. Нечитаемый существующий каталог registered-проекта также даёт диагностику доступа, не молчаливое missing.

Нормализация не меняет входные объекты и не клонирует/замораживает произвольный граф data адаптера. Необязательное поле со значением undefined трактуется как отсутствующее; null не заменяет отсутствие и отвергается там, где не объявлен отдельно. На время одной операции состав, порядок и размеры фиксируются. Рендер не перечитывает изменённый массив между слайдами. Для сервера загруженная конфигурация определяет состав до её явного обновления/перезапуска; автоматическое наблюдение за исходниками не добавляется в B1.

## Deck

| Поле | Registered | Discovery |
| --- | --- | --- |
| `id` | Обязательно, уникально внутри Project | То же |
| `label` | Обязательное непустое отображаемое имя | То же |
| `width`, `height` | Положительные безопасные целые числа в CSS px; отсутствующая ось получает 1920 или 1080 | То же; размеры относятся ко всем обнаруженным артефактам колоды |
| `slides` | Обязательный массив Slide, включая пустой | Запрещён: состав даёт обнаружение |
| `artifactPrefix` | Обязателен при legacy layout, запрещён в stable | Обязателен; задаёт допустимое семейство папок |
| `expectedSlides` | Необязательное неотрицательное целое, равное длине slides; 0 допустим для черновика | Не поддерживается как гарантия авторского состава |
| `data` | Необязательный объект адаптера | Необязательные данные профиля чтения |

Порядок колод задаёт decks. Registered не пересортировывает slides по ID, имени файла, templateRef или старому no. Общая модель допускает разные размеры слайдов; конкретный exporter вправе отвергнуть неподдерживаемую комбинацию с диагностикой. Никакого скрытого масштабирования или выбора единого размера за пользователя нет.

## Slide

| Поле | Правило registered v1 |
| --- | --- |
| `id` | Обязательный ID экземпляра, уникален внутри Deck; сохраняется при перестановке и локальной правке |
| `name` | Необязательное отображаемое имя; если отсутствует, используется id |
| `width`, `height` | Необязательные overrides отдельных осей; каждая отсутствующая ось наследуется от Deck |
| `data` | Объект содержания/настроек, принадлежащий адаптеру; движок не требует конкретных полей |
| `artifactNo` | Только для legacy layout: обязательная уникальная в Deck цифровая строка, например `01`. Это часть пути, не номер показа |

`index` — вычисленная позиция от 0, `number` — номер показа от 1. Они не задаются автором в конфиге. В подготовленном описании доступны постоянный id, вычисленные index/number, эффективные width/height и разрешённые пути артефактов. Движок вычисляет это один раз для всех потребителей результата; scanner не заменяет размеры значениями Deck.

Полная ссылка на слайд — `(project.id, deck.id, slide.id)`. Одинаковый локальный slide.id разрешён в разных колодах. Перенос между колодами меняет полную ссылку и должен быть явной будущей операцией F; B1 не обещает глобальный ID экземпляра вне Deck. Копия в той же колоде обязательно получает новый id. Ссылка на шаблон, если она есть в data, не является ID экземпляра.

У registered-слайда отсутствует авторское поле no. В compatibility-представлении 0.1 поле no сохраняет прежнюю строку; оно не превращается молча в новый number.

## Идентификаторы

Project.id, Deck.id и Slide.id — непустые ASCII-строки из `[A-Za-z0-9_-]+`; пробел, слеш, точка, `..`, разделитель URL или NUL недопустимы. Имена и подписи могут быть на русском и не используются как пути. Для ручных ID рекомендуется lowercase, но он не навязывается преобразованием.

Ссылки в API используют точное написание ID. При проверке уникальности внутри области дополнительно сравнивается ASCII lowercase: `Intro` и `intro` не могут быть двумя сущностями одного scope на разных ОС. Изменение написания ID, включая регистр, является явной заменой ссылки, а не перестановкой. Ошибка не исправляется автоматическим переименованием.

artifactPrefix — отдельная непустая строка с той же безопасной ASCII-грамматикой; уникальна во всём Project с учётом lowercase-сравнения, даже у пустых колод. Нельзя назначить две колоды одному семейству папок. У artifactNo только цифровая грамматика `[0-9]+`; уникальность сравнивается как строка, поэтому `01` и `1` — разные ключи файлов.

ID не генерируется из позиции. Нормализованная строка `01` не приравнивается к `1`. Для индексов реестра нельзя интерпретировать ID как свойство прототипа JavaScript. Ограничения пути и размеров backend проверяются отдельно: допустимый логический ID/целый размер не обещает поддержку любого абсолютного пути или неограниченного canvas.

## Пустые и ошибочные состояния

Пустой Project и Deck валидны как черновик для просмотра и дальнейшего создания содержания. Отсутствующее поле decks/slides не равно пустому массиву. Viewer показывает пустое состояние; он не добавляет старые артефакты в registered-проект.

Рендер без доступной колоды сообщает отсутствие цели. Рендер явно выбранной пустой колоды сообщает EMPTY_DECK до записи файлов. `--deck=all` проверяет всю выбранную область заранее: пустая или ошибочная колода требует исключить её из выбора или наполнить, а не молча пропускается. Валидация не создаёт фиктивный слайд и не удаляет чужие файлы.

Категории для реализации B2: неизвестная версия/режим, неверный тип/путь поля, дубликат ID или пути, конфликт источника, несовпадение expectedSlides, отсутствие renderer для операции и пустая цель. Ошибка содержит код, путь поля и контекст колоды/слайда. Точная форма error/result и политика частичного выполнения задаются C2; B1 не вводит новый публичный класс ошибок.

## Пути и артефакты

| Профиль | Каталог слайда | Файлы |
| --- | --- | --- |
| Stable | `<root>/deck-<deck.id>/slide-<slide.id>/` | `render.html`, `generated-html.png`, `qa.md`; опциональный `spec.md` |
| Legacy | `<root>/<artifactPrefix>-<artifactNo>/` | `<prefix>-<artifactNo>-render.html`, `generated-html.png`, `<prefix>-<artifactNo>-qa.md`; опциональный `<prefix>-<artifactNo>-spec.md` |

Stable layout отделяет scope колоды от слайда; служебные префиксы не позволяют ID вроде `con` стать именем Windows device-каталога. Итоговые пути уникальны во всём Project, остаются внутри root/outputRoot и проверяются на конфликты с mount и служебными результатами. Проверка границ учитывает разрешение существующих symlink/junction, а не только строковый префикс. B1 не назначает универсальный предел длины пути или объёма canvas; ограничения backend сообщаются до записи.

Default reportName пока сохраняет `render-report-<deck.id>.json`; существующий hook остаётся доступен и возвращает одно имя файла, не путь. Имена отчётов уникальны внутри Project, в том числе без учёта ASCII-регистра, и не пересекаются с каталогами слайдов/служебными результатами. Для выбранной операции до первой записи разрешаются и проверяются все потенциально конфликтующие имена Project. reportName должен быть чистым синхронным вычислением имени; изменение времени его вызова с конца рендера на preflight явно включается в migration guide. Схема отчёта и целостный manifest сборки относятся к C2/C4. Legacy reportName не переименовывается автоматически.

При переупорядочивании ID, artifactNo и пути не меняются. Удаление Slide из registered-конфигурации исключает его из API/viewer/нового рендера; оставшаяся папка не удаляется автоматически. Cleanup — отдельная операция вне B1. Stable HTTP-доставка использует зарезервированный namespace `/artifacts/`, legacy продолжает иметь адаптируемые старые пути; кодирование конкретного wire payload и маршрутов не становится новым HTTP API в B1.

root — исходная база артефактов, outputRoot — цель конкретного рендера. В v1 конфигурационные root/staticMount paths абсолютные и не зависят от cwd; относительный `--output` пока сохраняет разрешение от cwd как в 0.1. Для отдельного outputRoot адаптер получает baseUrl исходного каталога соответствующего профиля; движок не переписывает относительные ресурсы под новую структуру молча. Переносимость и общий resolver ресурсов — C1/D4.

## Доступность артефактов

Registered-описание содержит каждый заявленный Slide, даже если он ещё не рендерился. HTML и PNG имеют независимое состояние: `missing`, `available` или `unreadable`. У доступного файла известны его путь/URL; у недоступного есть диагностика. `available` означает доступный файл, не успешный QA, актуальность содержания или принятие слайда.

Viewer использует HTML в поддерживаемом режиме; при отсутствии HTML может показать доступный PNG. Когда отсутствуют оба, остаётся placeholder зарегистрированного слайда. Ошибка загрузки присутствующего HTML видна пользователю; незаметная подмена на PNG не скрывает её. Проверка свежести результатов и принадлежности одной сборке не выводится из mtime/size — это отдельный C4.

## Discovery

Discovery — явный read-only профиль для существующих legacy-папок. Он не требует renderDocument, не принимает slides и не поддерживает операции записи. Даже наличие функции в конфигурации не даёт ему renderer-capability.

Состав ограничен root и зарегистрированными artifactPrefix; используется цифровое окончание папки, числовая сортировка и разрешение равных числовых значений по ASCII-порядку строки имени, независимо от locale. Обнаруженный ID определяется именем папки, а не является ID авторского экземпляра. Равные ID с разным регистром сообщают конфликт. HTML/PNG обнаруживаются независимо; папка без обоих не выдаётся за обнаруженный слайд, но может дать диагностику NO_ARTIFACTS. При нескольких картинках ранжирование 0.1 сохраняется как legacy-правило до отдельного изменения контракта.

Переименование папки меняет идентичность discovery-артефакта. Импорт в управляемую презентацию с постоянными ссылками — будущая явная операция F. Нельзя объединять обнаруженные папки с registered slides одним скрытым merge.

```js
const path = require('node:path');
module.exports = {
  contractVersion: 1, id: 'neutral-archive', mode: 'discovery',
  root: path.join(__dirname, 'existing-output'),
  artifacts: { layout: 'legacy' },
  decks: [{ id: 'archive', label: 'Архив', artifactPrefix: 'demo-slide', width: 1280, height: 720 }],
};
```

Это иллюстрация предлагаемого v1-профиля, а не конфиг, поддержанный 0.1.0.

## Вызов адаптера и граница публичного API

В v1 renderDocument получает метаданные выбранных Deck/Slide, data адаптера, эффективные размеры и вычисленную позицию; третий аргумент сохраняет baseUrl. Callback не изменяет авторитетный состав операции. Старые hooks в legacy bridge получают прежние исходные Deck/Slide и поля контекста через обёртки; перенос deck.styles в data не выполняется автоматически.

Точки входа `deckloom`, `deckloom/node`, `deckloom/qa`, createRenderer/createReviewServer/startReviewServer и CLI dev/render сохраняются как оболочки. B2 может сначала ввести внутреннюю нормализованную модель. Поддержка versioned-конфигурации объявляется только после согласованного end-to-end прохождения B2–B4; один новый парсер не делает v1 рабочим для всего runtime.

Для registered v1 renderDeck выбирает колоду из реестра по id. Второй переданный массив slides не становится новым источником состава; другая колода или override определяются новым Project/явной будущей операцией выбора. Legacy-вызов renderDeck с переданной авторской колодой остаётся отдельным compatibility-сценарием, пока он поддерживается переходной оболочкой.

### Минимальная проекция чтения

Публичные scanDecks/scanSlides и HTTP `/api/decks`, `/api/slides` сохраняют точки входа. Явный `contractVersion: 1` конфигурации выбирает проекцию чтения v1; unversioned bridge сохраняет проекцию 0.1 для прежних клиентов. Это граница версии, указанная в конфиге и migration guide; нельзя переключить старый payload просто потому, что внутри появился новый нормализатор. Viewer, поставляемый с новой версией, должен поддерживать обе проекции. B3 реализует этот слой до объявления end-to-end готовности v1.

Проекция списка v1 имеет `contractVersion: 1`, generatedAt, project с id/mode и массив decks. Deck содержит id/label/default width/height и slides: в авторском порядке для registered, в порядке обнаружения по правилам Discovery для discovery. Slide содержит id/name/index/number/effective width/height и artifacts.html/artifacts.png. index/number вычисляются по полученному порядку в обоих режимах. Для одного Deck используется та же метаинформация с полем deck вместо decks; отсутствие запрошенного id — управляемая ошибка, не выбор первой колоды.

Артефакт содержит state; available дополнительно содержит URL и opaque version для обновления preview. Этот version может использовать stat для cache invalidation, но не является ревизией содержания/доказательством свежести C4. missing не содержит пригодного URL; unreadable содержит диагностическую категорию. Данные data, Node callbacks и абсолютные пути файловой системы в HTTP-проекцию автоматически не передаются.

В проекции v1 нет no. Для registered id — ID экземпляра, не выводимый из имени папки; для discovery id соответствует папке и не обещает идентичность авторского экземпляра. В проекции 0.1 сохраняются прежние значения id/no/file/htmlUrl; no не подменяется number. Исправление порядка/состава и размеров применяется с явным описанием отличий. Для legacy input сохраняется прежний путь к артефакту; для v1 стабильный namespace доставки — `/artifacts/`. Точные шаблоны URL кодируются B3 по выбранному layout, но не выводятся клиентом из number. Общие API-results/errors/CLI уточняются C2 без повторного выбора семантики этой проекции.

## Пример registered v1

Это полный иллюстративный конфиг предлагаемого контракта. В 0.1.0 он не исполняется как v1.

```js
const path = require('node:path');
module.exports = {
  contractVersion: 1,
  id: 'neutral-project',
  mode: 'registered',
  root: path.join(__dirname, 'output'),
  decks: [{
    id: 'intro', label: 'Введение', width: 1280, height: 720,
    slides: [
      { id: 'cover-main', name: 'Обложка', data: { title: 'Презентация «Deckloom»' } },
      { id: 'cover-meeting', name: 'Вариант для встречи', data: { title: 'Отдельный экземпляр' } },
    ],
  }],
  renderDocument(deck, slide) {
    const text = slide.data.title.replace(/[&<>"']/g, char => ({ '&': '&amp;', '<': '&lt;', '>': '&gt;', '"': '&quot;', "'": '&#39;' })[char]);
    return `<!doctype html><html><head><meta charset="utf-8"><style>
      html,body{margin:0;width:${slide.width}px;height:${slide.height}px}
      .slide{box-sizing:border-box;width:100%;height:100%;padding:64px;font:48px Arial;background:#f4f1e9;color:#17221c}
    </style></head><body><main class="slide">${text}</main></body></html>`;
  },
};
```

Перестановка двух элементов меняет number, но не id и не stable-пути. Замена title первого элемента не меняет второго. В B1 нет template renderer: одинаковое происхождение двух примеров ещё не является реализованной библиотекой F.

## Приёмочные сценарии B2–B4

Это спецификация приёмки B2–B4. Выполненные проверки перечислены в [B2](../tasks/b2-normalization-2026-10-20.md), [B3](../tasks/b3-read-registry-2026-10-20.md) и [B4](../tasks/b4-runtime-2026-10-20.md). Дальнейшие HTML/resource profile, API/hooks и build manifest относятся к C.

| Сценарий | Ожидаемый результат | Реализация |
| --- | --- | --- |
| Пустой Project/Deck | Валидный черновик; render сообщает пустую цель без записи | B2/B3 |
| Нет slides или decks | Ошибка обязательного поля; отсутствие не заменяется [] | B2 |
| Два одинаковых ID или case-only коллизия | Ошибка с областью/путём поля | B2 |
| Повтор artifactPrefix или prefix в stable | Ошибка профиля/уникальности, даже у пустых колод | B2 |
| Два reportName либо конфликт с каталогом | Ошибка до первой записи; проверка без учёта регистра | B2/C3 |
| Переставлены 02/01 либо произвольные ID | Сохраняется авторский порядок, identity/path неизменны | B3 |
| Один шаблон повторён | Два разных экземпляра, независимые данные | B2/B3; библиотечная изоляция — F |
| В папке остался удалённый слайд | Не появляется в registered, файл не удаляется | B3 |
| Старый no переименован в number | Не происходит автоматически; прежний no сохраняется как artifactNo/data | Migration/B2 |
| Override одной оси | Вторая наследуется; эффективные размеры совпадают во всех представлениях | B4 |
| Ноль, NaN, дробный размер | Ошибка поля; неподдержанный backend-размер — отдельная диагностика | B2/B4 |
| Нет PNG, есть HTML | Слайд остаётся доступен для HTML | B4 |
| Нет обоих/нечитаемый файл | Placeholder/диагностика зарегистрированного слайда | B4 |
| Discovery со slides или попыткой render | Конфликт источника либо read-only ошибка до записи | B2/B3 |
| Legacy layout и новый порядок | Старые имена файлов и ресурсы сохраняются | B3 |
| Legacy no равен intro | Нет молчаливого numeric-переименования; нужен явный перенос пути | Migration/B2 |
| Старый и versioned клиент чтения | Bridge отдаёт проекцию 0.1, v1 — явную версию и номер отдельно от id | B3 |
| Разный cwd и абсолютный root | Одинаковая база путей; относительный CLI output остаётся явным исключением | B2 |
| Неизвестная contractVersion/поле | Управляемая ошибка, без угадывания старого формата | B2 |
| Нормализация конфигурации с adapter data | Данные не интерпретируются/не публикуются автоматически; вход не меняется | B2 |

## Альтернативы и причины выбора

| Вариант | Польза | Цена | Выбор B1 |
| --- | --- | --- | --- |
| ID равен текущему номеру | Просто начать | Перестановка меняет ссылки и артефакты | Отдельные ID/index/number |
| ID уникален глобально | Удобнее переносы между колодами | Требует общей выдачи ID и лишних ограничений для независимых HTML-проектов | ID внутри Deck и явная полная ссылка |
| Всегда старые flat-пути | Меньше миграции | Технический номер остаётся обязательной частью новых проектов | Stable по умолчанию, legacy по явному выбору |
| Автоматически сливать slides и папки | Показывает всё найденное | Возвращает удалённое и создаёт второй источник порядка | Раздельные registered/discovery |
| Сделать конфиг сразу сохраняемым JSON | Рано появляется единая схема | Теряются адаптеры с кодом, преждевременно определяется F | Runtime-конфиг отдельно от документа F |
| Требовать JSON-safe data от любого HTML-адаптера | Проще будущая сериализация | Необязательная миграция существующего кода | data непрозрачно; сериализация — отдельная capability |
