## Согласованный результат и реализация

Первый случай E4 — ограниченные Grid-карточки. [Контракт E4](../contracts/pptx-e4-grid.md), пример — `examples/pptx-grid.config.cjs`. Общая подготовка DOM в `src/pptx.cjs` принимает явные `grid` → `card` → `text/rect/image` markers. Chromium определяет фактическую геометрию; фон карточки становится native rect, дочерние text/rect сохраняют редактируемость. Grid сам не создаёт отдельной фигуры, PowerPoint grouping не вводится. Исходный HTML/DOM не меняется; отдельной модели текста/композиции нет. Flex, произвольный HTML/CSS и остальные типы матрицы не добавлены.

`pptx-verification.json` и manifest содержат `conversion.version:1`: точный путь/hash сохранённого подготовленного HTML, контейнеры, source ID/path, bounds, native shape order, тип, реальный OOXML shape ID и применённые преобразования. Перед публикацией mapping проверяется по нормализованному PPTX XML на identity/kind/geometry; расхождение даёт `PPTX_MAPPING_MISMATCH`. Unsupported layout даёт `PPTX_UNSUPPORTED_HTML` с source ID и причиной, без частичной публикации. Grid/text/rect не растеризуются. Существующий SVG PNG compatibility fallback отражён отдельно от `rasterizedObjects`; исходный SVG сохраняется. Профиль Arial/Windows/960×540 и vendor/backend normalization не менялись.

Контейнеры должны иметь finite positive bounds, visible overflow и не создавать неподдерживаемый paint. Grid прозрачен, карты имеют solid background, auto row placement и не пересекаются. Дочерние объекты остаются внутри карточки. Grid не пересекается с другими top-level объектами: это консервативное ограничение исключает отличие CSS paint order при flattening. Decorations на grid/card запрещены, чтобы inherited visual underline не терялся. Лимит 256 native объектов учитывает фон каждой карточки; 512 declared nodes и 64 cards/grid ограничивают структурные контейнеры. Владение визуальным стилем и брендом остаётся у adapters; Monq/Unica не затронуты.
