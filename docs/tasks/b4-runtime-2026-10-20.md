# B4 V1 renderer, размеры и состояния HTML/PNG

20 октября 2026 года. Статус: B4 реализован и проверен локально. Разрешено: согласовать размеры и состояния API/viewer/renderer по B1, открыть v1 rendering и проверить сквозные сценарии. Monq и последующие этапы C–J вне области. Существующие A/B1/B2/B3 в рабочей копии сохранены; ветка master, без commit/push/publish и без назначения нового релиза.

## Реализация

- src/project.cjs: общий snapshot вычисляет оси и позиции. Read preflight ограничен конфигурацией/root/именами, leaves инспектируются независимо; render сохраняет строгие physical path/alias/type проверки. V1 selection выбирает канонический ID, unversioned raw-deck override сохранён. PNG backend имеет явный budget до первой записи.
- src/renderer.cjs: v1 и legacy используют метаданные prepared plan, включая viewport. Нормализованные hooks сохраняют legacy wrappers и передают v1 data/позиции/эффективные размеры. Default v1 QA исключает data; report.slide становится ID только для v1, legacy no не переосмысляется.
- src/artifacts.cjs: HTML/PNG инспектируются независимо; missing отличается от NOT_FILE/NOT_DIRECTORY/ACCESS_DENIED/PATH_ESCAPE/BROKEN_LINK/IO_ERROR. Неисправный leaf не удаляет зарегистрированный слайд из ответа. Legacy ranking сохранён, optional htmlError/imageError объясняют unreadable в прежней плоской проекции.
- Viewer использует общий размер frame, предпочитает HTML, допускает PNG при missing HTML и показывает ошибку unreadable/failed HTML. Decode PNG и пустой HTML не скрываются. Временные ошибки повторяются после healthy API polls без вспышки пустого содержимого или повторов pending-запросов; удачный preview не загружается заново на каждый poll.
- examples/render-v1.config.cjs и установленный consumer проверяют полный v1 runtime через прежние package exports и CLI. Потребительская презентация не требуется.

[Контракт B4](../contracts/render-v1.md) фиксирует вызовы, размеры, budget, hooks, состояния, retries и границы C1–C4. [Карта перехода](../migrations/project-contract-v1.md) описывает изменения для старых клиентов. Available означает читаемый файл; QA/freshness/build transaction не реализуются скрыто в B4.

## Ревью и проверки

Независимый reviewer проверил v1 selection, snapshots, legacy callback compatibility, read/write границу, размеры и классификацию FS. Найдено зависание failed preview до reload при неизменных metadata. Исправлено bounded retry на healthy poll; повторный Chromium repro подтверждает восстановление HTML/PNG ровно вторым запросом, без лишних запросов после успеха. Постоянная регрессия проверяет неизменность DTO/stat versions.

test/runtime.test.cjs содержит 7 сквозных сценариев: stable/legacy v1 paths+hooks+PNG/API/viewer, per-axis legacy inheritance/default, pre-write empty/canvas/path failures, независимые 12 состояний leaf/preview с заменой файлов, isolated resource baseUrl, transient retry и discovery/legacy unreadable. Реальный Chromium используется для PNG/header, viewer frame/aspect ratio, focus/overview/narrow, decode/network и восстановления. EACCES воспроизводится детерминированной инъекцией fs.access на конкретных файлах без изменения Windows ACL.

Первый прогон нового набора выявил ошибки самих проверок: offsetWidth/visibility измерялись у скрытых focus-карточек. Исправлена методика: все frame измеряются в overview, активные проверяются в focus. Реализация размеров ради теста не менялась. Focused B4 набор прошёл 7/7, после чего полный набор прошёл 35/35.
