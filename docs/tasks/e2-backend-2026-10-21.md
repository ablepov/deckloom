# E2 — проверенное решение о backend PPTX

Источник: запрос пользователя 21.10.2026 «разберись с упаковкой, шрифтами и зависимостями, зафиксируй backend и поддерживаемое подмножество; доведи до проверенного решения с ревью; E3 и Monq не трогай». **E2 завершён как проверенное решение**, отдельно от реализации E3. Единственный writer — lead; review read-only. Ветка master, существующие A–E1 изменения сохранены.

Основной источник решений — [решение E2](../decisions/pptx-backend-e2.md), повторяемая проба — [private harness](../../experiments/pptx-e2/README.md). В E2 нет публичного PPTX API/CLI, новой зависимости движка, правки Monq, commit/push или публикации.

Выбран структурированный PptxGenJS 4.0.1 + JSZip 3.10.1 в CJS bundle Node22, с узким normalizer и явной reference font policy. Проверяются настоящий tarball во внешнем npm consumer без overrides, actual included components/audit, повторная сборка, известные package corrections/negative cases и Office rendering/edit/save/reopen. Font embedding и hybrid не выданы за реализованные возможности. Поддержанный начальный профиль — native text/runs, solid rects, PNG и SVG resource; границы подробно в decision.

Независимый Astra Medium reviewer сначала проверил font/backend policy и packaging boundary, затем конкретный код/evidence. Исправлены найденные расхождения: проверка text/runs стала однозначной и соответствует экспорту; добавлены CR/CRLF и canvas guards; описание проверки orphan parts сужено до реально проверяемых orphan CT overrides/missing relationship targets, отсутствие полного reachability validator оговорено. Дополнительная проверка атрибуции выявила unmarked Microsoft helpers banner, который esbuild не сохраняет автоматически; теперь он целиком перенесён в notices. Reviewer сверил текст/hash и содержимое реального tarball. Повторное ревью финального прогона не обнаружило существенных препятствий для принятия E2. Reviewer не менял файлы и не выполнял Office-записи; Office-проверка выполнена lead.

Raw, normalized и edited PPTX, PNG из PowerPoint, prepared HTML/PNG D, package correction report, policy negatives, inventory/notices, build/consumer audits и roundtrip evidence сохранены в указанном output. Старые A–E1 доказательства не удалены. Полные runtime 53 tests/123-slide baseline/package-install заново не выполнялись: production code и root dependencies не изменились; это проверено fingerprints. Удалённый CI, ESM загрузка и другие Office не проверены.

## Границы решения

Начальный профиль — reference fonts без embedding, native text/runs/solid rects, PNG и SVG graphic; canvas пробы 960×540. Нет обещания font portability, native editing содержимого SVG или arbitrary HTML/CSS. Strict отказывает при неподтверждённой возможности; hybrid — отдельная политика будущего расширения и сейчас unsupported. Интерактивная ручная правка и отсутствие repair не доказаны hidden COM opening; это обязательная отдельная приёмка E3. Normalizer — узкий proof, не полный OPC/ECMA validator, не общий sanitizer и не принятое требование Python для npm runtime.

Следующий шаг — E3 только по отдельному запросу: перенести выбранный путь в общий D/C pipeline с ограниченным подготовленным представлением, поддержать serializer/validation, встроить artifact/cancel/publication/пакетные проверки и выполнить реальную пользовательскую приёмку PowerPoint. E3 в этой задаче не начинался; Monq, потребители, ветки, commit/push/release не менялись.
