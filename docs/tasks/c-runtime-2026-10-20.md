# Этап C — исполнение и публикация

Источник: запрос пользователя 20 октября 2026 года — автономно закрыть C1–C4, с самопроверками; Monq и другие потребители не менять. A/B1–B4 уже находятся в рабочей копии. Ветка master; публикация, commit/push и смена ветки не разрешены.

План: C1 сравнить inline CSS rewriting с document preview на нейтральных ресурсах и выбрать профиль; C2 отделить объектный render API от CLI; C3 ограничить ожидания hooks/readiness и сохранить диагностику; C4 публиковать manifest и согласованный набор артефактов. Затем независимое ревью, регрессии и проверка реального пакета.

Решение по C4 после независимого read-only ревью Astra: неизменяемые поколения на колоду, один атомарный publication pointer, URL с build ID и сервер, который его учитывает. Неудачная попытка сохраняет manifest, прежняя публикация остаётся доступной. Старые canonical файлы — совместимое зеркало без транзакционной гарантии для внешнего прямого чтения. Генерируемые HTML/PNG/spec/QA/report входят в сборку; ресурсы адаптера остаются внешними и изменяемыми до D4. --deck=all публикует колоды независимо. Один writer на outputRoot; поколения пока не удаляются.

Проверки: статический HTML с head/inline/external CSS, локальный тестовый шрифт, SVG/PNG и relative URLs; геометрия/выделение текста/изоляция CSS; типы/ошибки hooks, таймауты, progress/cancel, отсутствие глобальных побочных эффектов API; ошибка посередине колоды, pinned URL после новой публикации, повреждённый manifest, параллельный writer, отдельный outputRoot. Обязательны check/test/baseline/package и published 0.1 baseline.

## Результат

C1–C4 реализованы и проверены в рабочей копии. В npm ничего не опубликовано, версия и package-lock не изменялись. Monq/другие потребители не читались и не изменялись. Работа остаётся в master вместе с сохранёнными изменениями A/B; commit/push не выполнялись.

- C1: общий staticInspection для renderer/viewer, полноценный изолированный document preview v1, сохранение head/CSS/fonts/native URL resolution, явное исключение dynamic HTML и непереносимых resource modes. Нейтральный пример покрывает inline/external CSS, import, локальный авторский тестовый шрифт, SVG/PNG, relative base и пути. Ширина текста 96 px и цвет совпали; прямой HTTP document и PNG совпали по байтам. Проверены выделение текста, CSS-изоляция, размеры, focus/overview и narrow viewport.
- C2: render(options) с resultVersion/status/reports/builds/diagnostics/failures, progress и AbortSignal. Объектный deckId — exact ID (в том числе all), отсутствие deckId — все колоды; CLI сохраняет --deck=all и default первой колоды. Library не читает process.argv, не пишет console и не меняет exitCode. renderDeck/run сохранены с явной миграцией.
- C3: типы hooks/async/среда исполнения описаны и проверяются, async ожидания ограничены, Node/browser hooks дают stage/code, warnings fail/report, CSS/font/image/page diagnostics сохраняются. Ошибки вложенных CSS/background resources в same-origin preview восстанавливаются polling-ом без смены HTML metadata; ошибка остаётся видимой до готовности retry. Cleanup сохраняет основную ошибку и освобождает страницы/lock.
- C4: неизменяемые deck generations, versioned manifest и atomic publication pointer, pin build ID в read URL и server resolver. Failed/cancelled manifest хранит частичный состав. Старые URLs продолжают отдавать старые HTML/PNG после новой публикации. Ошибка на позднем слайде/поздней колоде, каждом artifact write, begin/commit pointer write и отмена перед commit не подмешивают файлы. Повреждённые manifests/отсутствующий declared файл видимы; control links и второй writer отвергаются.

## Самопроверки и независимое ревью

Lead выполнял реализацию единственным writer. Astra отдельно рассмотрел протокол публикации и затем проверил исправления. Его замечания: failed pointer commit, отмена у commit, cleanup, произвольный thrown value, authored relative base и schema validation. Все исправлены и закреплены отрицательными тестами. Повторная проверка не нашла publication blockers; шесть адресных тестов reviewer запустил успешно. Дополнительный край release-lock исправлен через finally.

Sol отдельно проверил C1–C3: недиагностированные CSS imports/background failures, исчезновение ошибки при retry и потерю hook stage. Исправления и browser regression подтверждены повторным read-only проходом; дополнительных blockers не найдено. Reviewer не меняли файлы и не делегировали дальше.

## Проверки

- npm run check: 25 modules и viewer script.
- npm test: 45/45, без skip; сохранены 35 предыдущих тестов и добавлены 10 сценариев C с несколькими fault cases внутри.
- npm run check:baseline: 123 слайда, focus/overview/narrow, 0 failures; последний полный прогон 29 074 мс на этой машине. Это измерение, не обещание производительности.
- npm run check:package: реальный tarball установлен вне checkout, проверены exports/imports, bytes runtime, старые CLI/API/ресурсы/viewer, v1 read/render/CLI и новый объектный API/progress без exitCode side effect.
- npm run check:package:published: действительный npm 0.1.0 прошёл прежний external-consumer baseline.
- Финальные syntax/test/package и dry pack прошли после последних runtime-правок. Проверены UTF-8, 20 Markdown-файлов / 88 локальных ссылок и git diff --check. Архив содержит 31 файл, 72 255 байт; все 10 runtime-файлов установленного пакета совпали с checkout. Evidence и копия локального tarball сохранены в output/validation/c.

Проверенная среда: Windows x64, Node 22.17.1, Playwright 1.59.1, Chromium 147.0.7727.15. Remote CI/Linux не запускались. Canonical mirrors не транзакционны для прямых внешних file readers; ресурсы не входят в generation (D4); synchronous infinite Node hook не прерывается Promise timeout; cross-origin resource timing ограничен браузером. Published 0.1.0 и готовность обновления конкретного потребителя не подменяются локальной приёмкой.

Следующий этап roadmap — D1, отдельная задача. Этап C не требует команды между C1–C4; весь согласованный объём доведён до приёмки.
