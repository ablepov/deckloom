## Контракт и реализация

[Документ v1](../contracts/presentation-document-v1.md), [переход F1](../migrations/presentation-f1.md), нейтральные данные — `examples/presentation-document.cjs`. `src/document.cjs` предоставляет read-only namespace `presentation` через существующие root и `/node` imports: normalize/serialize/deserialize/renameSlide/duplicateSlide/limits. Зависимости не добавлялись, действующий runtime config normalizer и renderer не менялись.

- Документ — одна колода `(projectId,id)`, slide identity — `(projectId,id,slide.id)`. ID spelling/order сохраняются, уникальность слайдов ASCII case-insensitive, lookup и refs exact-case. Размеры и name overrides не материализуются при отсутствии. Draft `slides:[]` допустим.
- `documentVersion:1` отделён от runtime `contractVersion:1`. Root dimensions обязательны, ID длиной до 128, поля схемы закрыты. Нет implicit migration, новых случайных ID или сохранения computed index/number.
- `template` хранит libraryId/templateId/opaque revision и JSON data; внешняя библиотека структурно упомянута, но не разрешается F1. `local` требует точного ID/revision из document compositions, несколько ревизий с canonical spelling допускаются. `authored` содержит JSON data без ref. Definition/data opaque; это не подтверждение рендеринга произвольных блоков.
- Rename меняет display name, сохраняя identity/order/refs. Duplicate вставляется после источника, требует caller-supplied new ID, сохраняет pinned refs, даёт независимые data и не размножает shared composition definitions. Это thin identity helpers F1; вложенные block IDs/internal refs остаются будущим F3/F4.
- JSON validator не допускает callbacks/undefined/Date/custom prototypes/cycles/accessors, sparse arrays, nonfinite numbers и negative zero; own keys сохраняются безопасно без prototype pollution. Нет вызовов getters/toJSON на data. Budgets — 8 MiB/64 depth/100000 nodes/4096 slides и composition revisions. Normalize работает с trusted JS input, не обещает sandbox/peak-memory isolation для arbitrary Proxy/огромных objects.
- Сериализация сохраняет JS JSON значения, не исходные whitespace/numeric lexemes/object identity. `JSON.parse` имеет стандартные last-member-wins и JS number precision semantics; отдельный arbitrary-precision/custom JSON parser не вводится.

## Ограничения и следующий шаг

F1 не импортирует runtime configs автоматически, не рендерит документ сам, не читает внешнюю библиотеку, не сохраняет файлы/восстановление и не предоставляет редактор. JSON artifacts созданы для верификации в output, это не API G1. Действующие исполняемые adapter data/callbacks по-прежнему допустимы в runtime configs; новый JSON validator к ним автоматически не применяется.

Следующий пункт документной ветки — F2: определения шаблонов, разрешение pinned revisions и независимые экземпляры. Его конкретный объём ещё не согласован; реализация не начата. Остальные типы E4 и потребители не затронуты.
