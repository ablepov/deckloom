# E3 — подключение PPTX к общему экспорту

Дата: 21.10.2026. Источник — прямой запрос пользователя: подключить выбранный E2 backend, проверить в PowerPoint, довести до проверенного результата с ревью; E4 и Monq не трогать.

**Статус: E3 закрыт по явной пользовательской приёмке 21.10.2026.** После проверки в Google Презентациях пользователь сообщил: «Все правильно, все работает хорошо, посчитаем, шаг выполнен, давай дальше двигаться». Пользователь принял имеющийся результат и разрешил переход дальше без ожидания активации Office. Технические проверки, видимое открытие PowerPoint без repair и пользовательская проверка Google Презентаций выполнены. Интерактивная правка текста/заливки через PowerPoint UI с save/reopen остаётся ненаблюдённой из-за неактивированного Office; это сохранённое ограничение evidence, а не незакрытый gate E3. Пакет не опубликован, версия остаётся 0.1.0; ветка master, без commit/push/переключения. Существующие изменения A–E2 сохранены. Потребители не изменялись.

## Зафиксированные решения и реализация

- [Контракт E3](../contracts/pptx-e3.md), [переход](../migrations/pptx-e3.md). Аддитивный format `pptx` в общем API/CLI; defaults и D strict font semantics сохраняются.
- Один HTML-источник из adapter, подготовка ресурсов D, затем внутренний `preparedVersion:1` из того же screen DOM до PDF overrides. Отдельной публичной PPTX-схемы и callback нет. Явные HTML markers принадлежат общему export authoring contract; контент, композиция, бренд и правила конкретного потребителя остаются в adapter.
- Узкий strict профиль: Windows/реально установленный Arial reference, uniform 960×540, native text/runs/solid rectangles и PNG/SVG pictures. Запрещены непроверенные CSS/DOM/font/canvas/resource capabilities. Hybrid/embedding, новые блоки и E4 не реализованы.
- C lock/cancel/timeout/публикация, результат с hashes и build-pinned URL используются для PPTX вместе с другими форматами. Raw backend, prepared representation и corrections сохраняются как диагностические build artifacts.
- Backend поставляется в `src/vendor/pptx`, рецепт/lock — `tools/pptx-backend`. Bundle SHA-256 `92f311ac1c6ea6268cb79bbd7e08b5b992831ca8097a39f72e02f56739412bd0`, 15 npm components с полными notices. Неиспользуемый image-size не включён; потребитель не требует overrides. Добавленный XML parser — @xmldom/xmldom 0.9.12.

E3 нашёл третий дефект PptxGenJS 4.0.1: одинаковые pPr перед каждым rich run внутри a:p. E2 не проверял cardinality этих свойств; [решение E2 явно уточнено](../decisions/pptx-backend-e2.md). Нормализация теперь исправляет только ожидаемые orphan master overrides, неправильный SVG PNG fallback и serialized-XML-identical повторы pPr на проверенных границах. Различающиеся properties/order/namespace дают отказ. Это целевая проверка pinned backend, не полный OpenXML validator.

## Самопроверки и независимое ревью

Один независимый read-only Astra/medium reviewer выполнял bounded architecture и implementation passes; автор изменений в checkout был один. Reviewer не менял файлы и не управлял Office. Существенные замечания и закрытие:

| Замечание | Результат |
| --- | --- |
| Терялись outline, text-indent, position/spacing/white-space/line-height spans | Закрытый список declarations + computed guards; Chromium negatives |
| Padding изображения менял content box относительно captured border box | Явный отказ; regression case |
| PNG CRC/header не доказывали декодируемость IDAT | Bounded zlib decode, scanline sizes/filters и узкий 8-bit noninterlaced профиль; malformed-IDAT negative; независимый Pillow |
| Inherited underline и pseudo paint могли отличаться | Наследование underline передаётся явно; неподдерживаемое сочетание цвета/декорации отвергается; pseudo-element rules запрещены |
| Background-clip:content-box мог менять область solid fill | Явная проверка border-box; negative на root и rect. Отдельно исправлен тест, где stylesheet правило перекрывалось inline shorthand и фактически не включало нужный clip |
| Повтор pPr требует узкой доказуемой нормализации | Предварительная проверка всех кандидатов, identical serialized XML, first/last positions, run boundaries, hashes/count/shape/paragraph, финальная cardinality и idempotence; reviewer подтвердил подход |

При визуальной проверке тестовой правки обнаружено и исправлено искажение литерала в BOM-less PowerShell 5.1 script. Теперь фиксированный текст передаётся через явное UTF-8 decode; независимый Python сравнивает точную строку `Правка — сохранено` в COM evidence и XML отредактированного PPTX. Повторный PowerPoint PNG визуально проверен.

### Реальный PowerPoint

Evidence — `output/validation/e3/final/`: `result.json`, `independent-verification.json`, `powerpoint/verification.json`, исходные/edited PNG и `edited.pptx`. PowerPoint 16.0 открыл конечный файл общего exporter, отрендерил три слайда, сохранил native текст, bold/italic/underline, точные строки, геометрию и порядок. Текстовая и shape-fill правки сохранились после save/reopen. XML независимо проверяет native text/rect/picture parts и сохранённый SVG; COM Font.Name не трактуется как доказательство отсутствия glyph fallback. Для исходного HTML glyph fonts независимо проверяет Chromium CDP.

Изображения PowerPoint и HTML просмотрены визуально. Для автоматических сравнений: native XML geometry — <0.01 CSS px, Office object geometry — <0.1 CSS px, последовательность строк и формат каждого символа — точные; text bounds остаются внутри объекта с допуском 3 pt для metrics. Pixel-perfect raster equivalence между Office и Chromium не заявлена.

### Наблюдаемая граница тестирования/cleanup

Неограниченная параллельность test files при нескольких Chromium/Office нагрузках периодически приводила к timeout **создания** страницы при `pageTimeoutMs:300`, до запланированного зависшего CSS. В borrowed browser оставался context до завершения позднего newPage и его callback close. Код этой cleanup-границы не менялся в E3; comparable pre-E3 load baseline отдельно не выполнялся, поэтому происхождение дефекта не доказывается одной хронологией.

По ревью ограничена параллельность browser suite двумя файлами, без ослабления assertions/deadlines. Тест зависшего stylesheet теперь дополнительно требует HTTP request, чтобы ранний newPage timeout не выдавался за document timeout. Полный набор 57/57 проходит. Это не исправление/доказательство мгновенной очистки контекста при unresolved newPage. Граница документирована в API C; возможный следующий hardening требует отдельного deterministic deferred-newPage теста с разрешением и после cleanup deadline. В E3 не добавлялась непроверенная смена timing/ownership или закрытие borrowed browser.

## История ограничения runtime

Windows computer-use skill применён; прочитаны guidance/API/confirmations. Инициализация `mcp__node_repl` с `@oai/sky` завершилась `failed to write kernel assets: Системе не удается найти указанный путь. (os error 3)`. После kernel reset повтор дал ту же ошибку до запуска app API. Другой UI helper не подменял разрешённый workflow, состояние рабочего стола не угадывалось.

На тот момент `visibleNoRepairObservation:false` в COM evidence честно отражал отсутствие UI observation. Историческое evidence не переписано; новая видимая проверка ниже хранится отдельно. Monq, новые блоки, embedding/hybrid и E4 для оставшейся приёмки не нужны.

21.10.2026 пользователь явно попросил сохранить движение roadmap внутри проекта и создать новый чат, где заново попробовать computer-use. Подготовлена [точка продолжения](../current-state.md), на которую ссылаются корневой AGENTS.md, README и roadmap. Предположение о связи ошибки с большой историей чата остаётся гипотезой; новая попытка должна проверить фактическую доступность runtime. Приёмка E3 этим организационным переносом не закрывается.

### Решение о закрытии E3 — 21.10.2026

Следующим прямым сообщением пользователь явно принял шаг выполненным и разрешил двигаться дальше: «Все правильно, все работает хорошо, посчитаем, шаг выполнен, давай дальше двигаться». Это новое решение заменяет прежний статус частичной приёмки и ожидание Office UI edit/save/reopen как условия закрытия **E3**. Оно не доказывает невыполненные действия и не устанавливает автоматически критерии приёмки новых возможностей E4.

E3 закрыт в development checkout по совокупности технического evidence, видимого no-repair открытия PowerPoint и пользовательской проверки Google Презентаций. Исторические поля `interactiveTextEdit:false`, `interactiveRectangleFillEdit:false`, `uiSaveTestCopy:false`, `uiReopenEditedCopy:false` не меняются. Ограничение Office сохраняется в контракте и current-state. Следующий шаг roadmap — E4; конкретное первое расширение подготовлено как [предложение](e4-scope-2026-10-21.md), реализация ещё не начата. Monq/другие потребители, commit/push/release этим решением не разрешены.
