# Этап D — экспорт

Источник: прямой запрос пользователя 20 октября 2026 года — автономно закрыть D1–D4, с самопроверками и независимым ревью, без изменения Monq. A–C уже находятся в рабочей копии master; сохраняем их. Публикация, commit/push и смена ветки не разрешены. Lead — единственный writer.

План приёмки: единый подготовленный запрос/выборка/описание outputs (D1), pixel scale/alpha PNG (D2), изолированные Chromium PDF страницы с проверкой геометрии/текста/шрифтов (D3), offline ресурсный граф с проверкой переноса без source/network (D4). Подэтапы проходятся без ожидания команды.

Принятые технические решения после независимого ревью Astra: export(options) использует существующий execute, один exact deckId, optional slideIds как множество в порядке Deck; отдельный outputRoot без пересечения с source/resources. PNG сохраняет CSS canvas и задаёт scale/alpha. Каждый Slide печатается отдельно и объединяется без растеризации; mixed sizes проверяются по итоговым page boxes. Default export — строгий offline профиль. HTML/CSS разбираются парсерами, включая неактивные imports/fonts/media/srcset/SVG; browser capture не заменяет обход графа. Исходники не меняются. Strict violations прекращают публикацию, в отличие от диагностируемых C QA findings. Прежние render/renderDeck/run и их defaults сохраняются.

Статус: D1–D4 реализованы и проверены в рабочей копии. Новый релиз не опубликован; существующие A–C изменения сохранены. Контракт: [export v1](../contracts/export-v1.md), переход: [миграция D](../migrations/export-d.md).

Публичные методы render/renderDeck/run остаются по C, новая возможность добавлена как export. Версия package.json/lockfile остаётся 0.1.0 development candidate. Runtime dependencies теперь включают публичные parse5 8.0.1, PostCSS 8.5.31, postcss-value-parser 4.2.0, pdf-lib 1.17.1. Нейтральный пример использует DejaVuSans с полной лицензией, сохраняемой также в HTML. Python нужен только для независимого verifier, не для npm runtime.

HTML/PNG/QA/report сохраняются как вспомогательные C artifacts даже для PDF-only. Запрошенные форматы перечислены в outputs; portable index/export manifest находятся в отдельном namespace и читаются через pinned HTTP build. Старая HTML-страница index после нового commit остаётся связана со старым поколением. Ошибки строгого графа/шрифтов/пагинации и отмена до commit не заменяют прежнюю публикацию. Cleanup failure после commit и QA failure могут сопровождаться уже опубликованным результатом — status и build state различаются по C.

## Самопроверки и независимые ревью

Read-only ревью выполняли отдельные Astra Medium (архитектура/API/PDF) и Sol Medium (ресурсный граф); writer оставался один. Это технические решения внутри прямо разрешённого D, без изменения потребителей.

Найдено и исправлено с регрессионными проверками:

- Canvas preflight больше не отвергает невыбранный oversized sibling; report namespace проверяется относительно всех колод; CLI отвергает bare/duplicate/empty/unknown flags.
- Fonts expected проверяются по PDF, когда он запрошен; print-only fallback не скрывается экранным инвентарём. Платформенная подмена требует явного разрешения и отражается в manifest.
- CDP font inspection detach сбрасывал media/features Chromium: они восстанавливаются перед дальнейшей работой, PDF дополнительно получает явное media. Проверены print CSS, фон и reduced-motion PNG. Background policy учитывает авторский important; неподдержанный конфликт псевдоэлемента даёт отказ.
- Закрыты escaped CSS functions/imports (в ревью дополнительно 60 вариантов import), SVG presentation URL attrs, imagesrcset, UNC до FS, CSS/SVG cycles и прежний риск взаимного ожидания cache promises.
- Строковые var/env/attr substitutions в image-set могут скрывать URL в inactive CSS: они теперь требуют static preparation. Повторное ревью проверило 53 варианта substitution/escapes без оставшегося воспроизводимого обхода.
- Readiness использует успешный image.decode(), поскольку Chromium при DPR 1.5 может округлять naturalWidth маленького srcset image до 0. Это согласовано с v1 viewer и покрыто сценарием.

Оба ограниченных повторных ревью завершены без оставшихся существенных находок в проверенных изменениях. Уточнение документации о cleanup после commit принято. Это не универсальное доказательство поддержки любых HTML/CSS-конструкций; поддержанный профиль и явные отказы описаны в контракте.

## Границы и следующий шаг

Strict offline не поддерживает произвольную сеть, динамический DOM/SMIL, UNC, source escapes, local fonts, unresolved image-set substitutions и внешние переходы ссылок. External SVG text в strict требует paths или разрешённой подмены. Resource limits, color-policy конфликт и font-policy ограничения явны; allow-substitution ограничивает переносимость оформления HTML. Bundle является снимком результата, не редактируемым документом F/G. Размеры PDF округляются Chromium в заявленном допуске, двоичная идентичность PDF не обещается.

Следующий небольшой этап по roadmap — E1: изолированная сравнительная проба DOM-конвертации и структурированного PPTX на нейтральных text/shapes/image+SVG примерах, с реальной проверкой PowerPoint и таблицей потерь. Она не реализована в этой задаче. Monq, другие потребители, commit/push, ветки и публикация не затрагивались; текущая ветка master.
