# Визуальные шаблоны и интерфейс редактора — отложенное предложение

## Источник и статус

Пользователь 21.10.2026: «Проверил новые PPTX в Google Презентациях, всё нормально, всё редактируется. Закрываем E4 и давай переходить к визуальной шаблонизации и интерфейсу редактора».

E4 принят. **Пользователь затем явно отложил редактор и выбрал доработку движка/экспорт Monq Retail16; текущая задача — [Monq Retail PPTX](monq-retail-pptx-2026-10-21.md).** Приведённое ниже предложение UI осталось несогласованным и не является текущим разрешённым объёмом. Конкретный первый сценарий/визуальная основа ещё выбираются; реализация нового UI или конструктора шаблонов не начата. Применён product-task-understanding; его требование — согласовать новое понимание до плана/реализации. Routing preflight: ограниченное исследование и документация выполняются локально, делегирование не требуется.

## Доказанные исходные данные

- F1–F4/G1 предоставляют document/catalog/definitions/commands/storage; E4 принят в заявленных ограниченных профилях. Проверки и решения — [предыдущая задача](autonomous-engine-2026-10-21.md).
- `viewer/index.html` — действующий просмотрщик с собственными CSS tokens; `src/server.cjs` предоставляет read API `/api/decks` и `/api/slides`. Это база просмотра, не готовый редактор документов.
- H1–H4 в [roadmap](../roadmap.md) описывают catalog → assembly → field editing → save/undo/export; I3 отдельно описывает визуальную сборку и сохранение нового шаблона. Выбор UI stack ещё не закреплён.
- Найденная визуальная база — локальные tokens/паттерны viewer. Отдельный согласованный источник дизайн-системы редактора в проверенных источниках не найден. Предложение: расширить общие правила Deckloom для editor workspace и фиксировать их в этой задаче/будущем общем UI-источнике, владелец — проект Deckloom; окончательный стиль выбирается совместно.

## Сценарии, которые нельзя смешивать

**Автор презентации:** есть содержание будущих слайдов; нужно выбрать подходящие композиции, поправить текст/изображения/тему и порядок, сохранить работу и получить редактируемый PPTX. Момент результата — презентация повторно открывается с правками, экспорт соответствует preview.

**Автор шаблона:** есть визуальная идея/образец; нужно собрать композицию, определить изменяемые поля и ограничения, сохранить повторно используемое определение. Момент результата — из него создаются независимые экземпляры с предсказуемыми правками и экспортом. Здесь затрагиваются также библиотечные операции G2/I3; объём существенно отличается.

Пользователь хочет участвовать в визуальном процессе; конкретная брендовая основа и первый приоритет из этих сценариев пока не заданы.

## Рекомендация к согласованию

Первый результат — локальный редактор презентации с небольшой совместно выбранной визуальной библиотекой: титул, текст с изображением, карточки и таблица. Предлагаемая рабочая область: список слайдов, крупный preview реального renderer и панель разрешённых свойств. Выбор шаблона создаёт независимый экземпляр; доступны текст/медиа/тема, порядок/копирование/удаление, сохранение/повторное открытие и экспорт с понятными ошибками/несохранённым состоянием. Старые документы и библиотечные определения сохраняют идентичность.

Это новый общий workspace-паттерн Deckloom поверх существующих команд, а не отдельная модель слайдов. Приёмка предполагает совместное подтверждение визуальных композиций, затем browser-проверку полного пользовательского сценария без ручной правки JSON. Конструктор новых шаблонов остаётся отдельным возможным первым приоритетом, если пользователь выберет его.
