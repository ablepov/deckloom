# Исходная точка Deckloom 0.1

Зафиксировано 20 октября 2026 года для этапа A. Runtime исходной точки — опубликованный `deckloom@0.1.0`, исходный коммит `10bc6339a8dbb688b083855b9fade2a0f44438ea`. Документ описывает существующий контракт и его ограничения; будущий контракт развивается по [roadmap](roadmap.md).

## Поддерживаемые сценарии

Проект предоставляет собственные HTML/CSS и ресурсы, регистрирует колоды, запускает локальный просмотрщик и получает HTML/PNG с диагностикой. Библиотека не предоставляет PDF/PPTX, сохранение редактируемого документа, библиотеку шаблонов или редактор блоков. Подключение не требует соседнего checkout движка.

Публичные импорты: `deckloom` и `deckloom/node` возвращают `createReviewServer`, `startReviewServer`, `createRenderer`, `scanSlides`, `scanDecks`; `deckloom/qa` возвращает `measureLayout`, `createLayoutMeasure`, `issueCount`. Поддерживается CommonJS. Node.js >=22, peer Playwright >=1.57 <2; текущая проверенная комбинация использует Node 22 и Playwright 1.59.1. Весь объявленный диапазон версий этим не подтверждается.

`deckloom dev --config=...` запускает сервер. `deckloom render --config=... --deck=all --output=...` запускает рендер. Опции в 0.1.0 используют форму `--name=value`. Без `--deck` берётся первая колода; без `--output` используется `project.root`. Сервер по умолчанию слушает `127.0.0.1`, порт 3000; без явно заданного порта пробует следующие 20 портов. Возвращаемый HTTP server можно закрыть обычным `server.close()`.

## Конфигурация текущего адаптера

| Поле | Наблюдаемое поведение 0.1.0 |
| --- | --- |
| `root` | Абсолютный путь предпочтителен; сервер и renderer разрешают относительный путь от cwd. Это корень артефактов, а не автоматически публикуемый checkout |
| `decks` | Массив колод; для нормального viewer/render-сценария он непустой |
| `deck.id`, `artifactPrefix`, `label` | Идентификатор, префикс файлов, название; ID и префиксы должны быть уникальны и использовать безопасные символы |
| `deck.slides` | Авторский массив для рендера; `slide.no` участвует в имени артефакта. Для совместимости со scanner используйте уникальные цифровые строки |
| `width`, `height` | Размеры колоды, по умолчанию 1920×1080; переопределение размера отдельного слайда не является согласованной гарантией viewer в этой версии |
| `renderDocument(deck, slide, {baseUrl})` | Возвращает строку HTML или Promise строки. При отдельном output root baseUrl указывает исходный каталог артефакта через file URL; адаптер разрешает ресурсы самостоятельно или использует `<base>` |
| `staticMounts` | Явные URL-префиксы/файлы для HTTP-ресурсов; пути должны согласовываться с file-based renderer отдельно |
| `viewer` | title, favicon, storagePrefix, legacyDeckId; позволяет разделить состояние просмотрщиков и перенести прежнее сохранённое состояние |

При рендере создаются `<prefix>-<no>/<prefix>-<no>-render.html`, `generated-html.png`, QA и опциональный spec. Отчёт колоды содержит пути и количества ошибок. Имена и порядок массива report следуют авторскому массиву слайдов.

## Хуки и ошибки

| Хук/метод | Контракт исходной точки |
| --- | --- |
| `validateDocument(html, deck, slide)` | Синхронный или async; исключение останавливает рендер |
| `renderSpec(deck, slide)` | Синхронный или async; строка markdown |
| `renderQa(context)` | Строка или Promise строки; renderer ожидает результат через await |
| `reportName(deck)` | Синхронное имя файла без каталогов |
| `measureLayout` | Функция исполняется в странице через page.evaluate, без замыканий на Node-переменные; layoutOptions передаются аргументом |
| `createLayoutMeasure(options)` | Создаёт самодостаточную функцию для page.evaluate; настройки сериализуются |
| `issueCount(layoutQa)` | Синхронное число ошибок |
| `renderDeck(browser, deck, {outputRoot})` | Использует переданный Playwright browser; закрывает свои страницы; возвращает массив report, включая QA/asset/console-сбои |
| `run(argv)` | Сам создаёт/закрывает Chromium, печатает summary, устанавливает process.exitCode=1 при layout/asset/console-сбоях |

QA-сбой в `renderDeck` сам по себе не означает rejected Promise. Ошибка загрузки страницы или хука может завершить вызов исключением до записи итогового отчёта. Для встраивания проверяйте report; CLI дополнительно возвращает exit code. Console warnings сейчас тоже считаются причиной неуспешного CLI-рендера.

Renderer ожидает `document.fonts.ready` и декодирование img. Проверка missingAssets относится к img; это не полная проверка CSS, фоновых ресурсов, шрифтов или вложенных ресурсов SVG. Отсутствующие изображения и page errors входят в диагностику.

Для встроенного QA корень слайда по умолчанию `.slide`. Проверяются видимый HTML-текст, пересечения, выход/обрезание и размеченные области вместимости. Потоковая вёрстка и одноимённый frame могут быть дополнительной политикой проекта, но не требуются от любого потребителя. QA не уменьшает шрифт автоматически и не подтверждает качество содержания.

## Известные ограничения

Эти наблюдения не превращаются в обязательную совместимость. Исправление требует явного описания нового поведения и регрессий соответствующего шага, а не сохранения дефекта.

| Ограничение | Наблюдение | Владелец следующего решения |
| --- | --- | --- |
| Состав и порядок viewer | Scanner обнаруживает папки и сортирует по номеру; не следует `deck.slides`; старые папки могут остаться видимыми | B1–B3 |
| Неполная валидация | Сервер и renderer проверяют вход по-разному; повтор номера слайда может привести к перезаписи артефакта | B2 |
| Идентификаторы | Renderer принимает безопасную буквенную строку, scanner/routes ждут цифровое окончание | B1–B3 |
| Размер слайда | Renderer может учитывать override, scanner возвращает размеры колоды | B4 |
| HTML без PNG | Scanner пропускает слайд без подходящей картинки | B4 |
| Произвольный HTML | Viewer удаляет scripts, переносит inline styles/body и теряет link stylesheet из head; CSS переписывается | C1 |
| Изолированный output | file-based baseUrl помогает локальному рендеру, но не делает каталог переносимым HTTP/offline-пакетом | C1/D4 |
| Результаты и запись | API связан с CLI, отчёт не версионирован, файлы публикуются отдельно | C2/C4 |

## Воспроизводимые проверки

```sh
npm ci
npx playwright install chromium
npm run check
npm test
npm run render:example
npm run check:baseline
npm run check:package
npm run check:package:published
```

`check:baseline` использует нейтральные две горизонтальные, одну вертикальную и 120 дополнительных горизонтальных страниц. Проверяет рендер, ошибки, размеры PNG, состав scanner на чистом корне и focus/overview/narrow viewport. Текст включает кириллицу, кавычки и тире. `npm run check:baseline:ci` — укороченная проверка с 24 дополнительными слайдами; произвольный размер задаётся командой `node scripts/check-baseline.cjs --large=N` для N от 1 до 500. Фикстура находится в `examples/baseline-fixture.cjs`, конфигурация для отдельного CLI-рендера — `examples/baseline.config.cjs`.

Измеряются длительность по колоде/всего, наибольший наблюдавшийся Node RSS (выборка раз в 100 мс) и версии среды. RSS не включает процессы Chromium. Это измерительная исходная точка для простой нейтральной вёрстки, не performance SLA и не оценка сложных схем/тяжёлых медиа. Каждый запуск получает новый корень артефактов и свой `baseline-result.json`; копия последнего отчёта — `output/validation/stage-a/baseline/latest.json`.

`check:package` упаковывает текущую рабочую копию; `check:package:published` получает точный опубликованный архив 0.1.0 из публичного registry. Другая точная версия задаётся командой `node scripts/check-package.cjs --published=X.Y.Z`. В обоих случаях архив проверяется и устанавливается в отдельный временный проект вне checkout. После установки исходный tarball скрывается, NODE_PATH и типовые token-переменные убираются. Проверяются публичные imports, установленный CLI, HTML/PNG, spec, локальный SVG, кириллица, ошибки CLI, API-render и viewer. Временный потребитель удаляется; архив и отчёт сохраняются в `output/validation/stage-a/package/<source>/`.

Именованные npm-команды не требуют пересылки опций после `--`: это обходит наблюдаемое поглощение аргумента оболочкой npm.ps1 в Windows. Если опция попала только в npm_config, проверка останавливается, а не подменяет выбранный режим локальным.

Локальный архив в этой задаче остаётся проверочным кандидатом с версией 0.1.0. Он не переиздаёт и не подменяет опубликованный пакет. Исполняемые src/bin/viewer исходной точки сверяются отдельно с исходным коммитом.

Локальные результаты и среда зафиксированы в [записи этапа A](tasks/stage-a-2026-10-20.md). CI запускает проверку на Ubuntu и Windows с Node 22; изменение workflow само по себе не подтверждает удалённый успешный запуск.
