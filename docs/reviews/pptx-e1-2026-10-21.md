# PowerPoint E1 — сравнительная проба

Источник: запрос пользователя 21.10.2026 «постепенно приступать к E» и согласованный roadmap. Область — E1: техническое сравнение на трёх нейтральных случаях и одном negative fixture. E2–E4 не реализуются; Monq, другие потребители и публичный API Deckloom не меняются. Предыдущие A–D изменения рабочей копии сохранены, ветка master, commit/push/release не выполнялись.

## Вывод

Оба подхода дают native text и простые редактируемые фигуры на этой выборке. Прямая DOM-конвертация пока непригодна как универсальная гарантия сохранения HTML: SVG через img тихо стал PNG, backdrop-filter пропал без сообщения. Структурированная сборка сохраняет SVG как отдельный SVG resource/reference и позволяет явно задавать native объекты, но сырой результат PptxGenJS содержит дефект упаковки. Ни один кандидат сейчас не включён в runtime.

Для E2 рекомендуется продолжить оценку структурированного подмножества с явными capabilities и проверкой пакета. Это рекомендация по результату E1, не принятое production API или обещание поддержки любых блоков. DOM candidate может рассматриваться для ограниченных простых сцен после собственной строгой проверки; маркетинговые заявления не заменяют доказательство.

## Метод и среда

Сравнивались dom-to-pptx 2.1.2 и PptxGenJS 4.0.1, MIT, в отдельном private package `experiments/pptx-e1`. Их lockfile отделён от root lockfile. Install выполнялся с ignore-scripts; чужие install hooks/skills installers не запускались. В runtime Deckloom не добавлены новые зависимости. Код и повторяемая команда находятся в [README эксперимента](../../experiments/pptx-e1/README.md).

Среда: Windows x64, Node 22.17.1, Playwright 1.59.1 / Chromium 147.0.7727.15, настоящий Microsoft PowerPoint COM 16.0. Размер — 960×540 CSS px, 10×5.625 in / 720×405 pt. Arial выбран исследователем как установленный системный шрифт; DOM autoEmbedFonts отключён для одинакового сравнительного условия. Это не проверка переносимого встраивания web fonts.

Одни fixture nodes содержат текст, runs, размеры и порядок. Для эталона вызывается `renderer.export()` этапа D с явно разрешёнными системными шрифтами; SVG/PNG включены в prepared HTML. DOM candidate получает именно этот HTML/ресурсы в Chromium. Structured candidate получает те же fixture nodes и размеры. Это временная схема эксперимента, не будущий публичный документ F или параллельная авторская модель текста.

Проба охватывает:

1. Кириллицу с ё/й/щ, «кавычками», тире, bold/italic/underline, автоматическим и явным переносом.
2. Два native прямоугольника с перекрытием и отдельными текстовыми объектами.
3. Локальные PNG и SVG одного технического маркера. Подготовка D включает их в data URLs, как и требуется автономному HTML.
4. Negative: обычные native цветные полосы и полупрозрачная панель с `backdrop-filter:blur(12px)`. Использованы прямоугольники вместо repeating-gradient, чтобы потеря градиента не смешивалась с проверкой blur.

PowerPoint через COM открыл, отрисовал, изменил title и native rect fill, сохранил edited copies и повторно открыл их. В обеих копиях подтверждён текст «Правка — сохранено» и новая заливка. Это реальное программное редактирование объектов в PowerPoint; интерактивная ручная правка не выполнялась. Hidden COM opening без исключения не доказывает отсутствия repair-процедуры. Полную E3-приёмку это не заменяет.

## Таблица наблюдений и потерь

| Случай | DOM candidate | Structured candidate | Значение для следующего этапа |
| --- | --- | --- | --- |
| Кириллический текст | 8 native text boxes на 3 слайдах, весь ожидаемый текст/порядок, bold/italic/underline | То же | Основной текст не превращён в картинку; пример после правки сохраняется |
| Переносы | Видимые строки совпали с Chromium | Совпали после явной сериализации breaks | Сравниваются строки с нормализацией whitespace, не byte-identical исходник; переносы нужны в общей приёмке |
| Фигуры/слои | Native rects; geometry и back/front z-order подтверждены | То же | На этой сцене есть редактируемые независимые объекты |
| PNG | Отдельная picture; изображение сохранено | То же | Нет full-slide flattening |
| SVG через img | В PPTX нет SVG part/reference, обе картинки PNG; `svgAsVector:true` не сохранил этот путь | SVG part + один svgBlip; PowerPoint type 28 graphic | DOM потерял vector fidelity. SVG graphic не равен набору native editable shapes; convert/ungroup не проверялись |
| Шрифты | Arial, embedded font parts отсутствуют | То же | Оформление зависит от установленного Arial. Встраивание, права и fallback других сред остаются вопросом E2/E3 |
| ZIP/XML/relationships | XML/targets и Content_Types проверка пройдены на этих файлах | Relationships/XML читаются, но есть два dangling Content_Types overrides | Нужен корректный backend/normalization и повторная приёмка до adoption |
| Negative CSS | Raw export создан без сообщений; blur визуально исчез | Negative scene в structured builder не создавалась | Нельзя считать DOM candidate fail-closed. Отдельный computed-style gate экспериментально отвергает backdrop-filter; этот gate ещё не часть движка |

Дефект упаковки structured файла: `[Content_Types].xml` ссылается на `/ppt/slideMasters/slideMaster2.xml` и `slideMaster3.xml`, которых нет в ZIP. DOM candidate выполняет свою normalization; в проверенных DOM-файлах таких orphan overrides нет. Сырой structured файл сохранён как доказательство дефекта, не исправлен незаметно. Отсутствие repair не заявляется.

Дополнительно обнаружено поведение PptxGenJS 4.0.1: rich run с внутренним LF заставляет следующий run перейти в новый paragraph. Экспериментальный serializer разделяет run заранее и ставит breakLine на предшествующий run. После этой ограниченной коррекции строки совпали с Chromium. Это fixture-level способ передачи явного переноса, а не универсальный алгоритм HTML text shaping.

## Проверки и доказательства

Финальный прогон: `output/validation/e1/2026-10-21T06-29-02-261Z`, статус `probe-complete-with-findings`. Там сохранены `dom.pptx`, `structured.pptx`, raw negative, edited copies, prepared bundle D, PNG из PowerPoint и JSON отчёты. Указатель — `output/validation/e1/latest.json`. Исходники/старые прогоны не удалялись.

Автоматические assert-проверки: весь ожидаемый native текст и его порядок с нормализацией whitespace, отсутствие replacement characters, font name Arial на непробельных символах, rich-run признаки, точное число picture объектов по fixture (исключает растеризацию целого слайда), видимые line chunks против браузерного Range measurement, размеры презентации, selected rectangle geometry с допуском <1 pt, z-order и результат edit/save/reopen. XML и internal relationship targets разбираются и проверяются. Dangling Content_Types сохраняются как finding, не маскируются успешным exit.

Средняя разница RGB между PNG PowerPoint и Chromium — диагностическая метрика, не самостоятельный pass threshold:

| Слайд | DOM | Structured |
| --- | --- | --- |
| Текст | 4.5039 | 4.5039 |
| Слои | 1.6104 | 1.8758 |
| Изображения | 1.3132 | 1.3077 |

Raw negative имеет mean RGB difference 8.5645; визуально видна потеря blur. Проверены PNG основных сцен и edited copies; отрисовка в других Office/ОС/браузерах не выполнялась. SVG outcome проверен по media list, svgBlip и Office shape type, не по объявлению опции.

Независимый read-only reviewer проверил harness и финальные evidence. Найденные gaps исправлены: lineWrapMatches теперь assert, а не только поле; количество picture объектов сверяется с fixture; negative отделён от repeating-gradient; hard-coded rejection заменён computed-style finding. Остаточных существенных gaps против ограниченного утверждения E1 reviewer не нашёл. Он не менял код и не запускал Office сам; Office-проверку выполнил lead.

`npm run check` прошёл. Runtime fingerprints всех 12 файлов src/bin/viewer сверяются с итогом D; root dependencies остаются прежними, experimental package не входит в npm archive. Полные 53 runtime tests/baseline/package-install заново не запускались: production code не менялся; новые сценарии проверены самим E1 harness и Office/inspector. Удалённый CI не запускался.

Npm audit экспериментального lockfile: 3 affected packages high через image-size 1.2.1 (dom-to-pptx и pptxgenjs также помечены как dependents), два DoS advisories. Это конкретный adoption blocker до выбора/обновления зависимостей; данный прогон работал только на собственных SVG/PNG и не является оценкой безопасности произвольных входов. Аудит не исправлялся через force и не менял root dependencies. Снимок — `output/validation/e1/audit.json`.

## Следующий небольшой шаг

E2 должен зафиксировать минимальные capabilities и backend только после проверки исправной упаковки и font policy. Сначала отдельная проба исправления dangling parts/выбора версии, затем текст + простые фигуры + PNG + SVG resource, затем strict отказ и явный hybrid fallback. Не расширять эту основу сразу на tables/diagrams/Grid/crop/shadows; они проверяются по одному в E3/E4. E2 пока не реализован, публичный `formats:['pptx']` не появился.
